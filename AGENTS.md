# Architecture rules
- Keep neighborhood action content synchronously rendered, fetch upcoming times from the existing booking function, and carry area/slot selections through URL parameters; booking revalidates selected times so availability is never invented or guaranteed.
- Keep standalone editorial articles synchronously routed with their content in a data module, article/author/breadcrumb metadata and route-registry sitemap inclusion; this preserves readable pre-rendered pages without restoring the removed blog system.
- Keep Reddit page content and source references in a shared data module, with a synchronous public route and homepage section, so search crawlers receive readable content and metadata without waiting for client loading.
- Keep authentication email dispatch in the scaffolded managed auth-email-hook SDK handler; the platform owns delivery and retries, so do not add email queues or cron infrastructure.
- Pre-render retired commercial URLs with the noindex NotFound page and exclude them from the sitemap; this prevents hosting fallbacks from serving indexable homepage content at retired URLs.
- Initialize the Google tag once in the browser through the public connector measurement ID; track route views and explicit funnel outcomes centrally without sending contact details or report content.
- Keep source homepage fallback metadata inside the marked block and strip it with the SSG pre-render hook, so source checks pass without duplicating route-specific heads.
- Generate the existing sitemap from the route registry before preview/build, omit unverified modification dates, and link nearby-area chips only to registered neighborhood routes to prevent navigation drift.
- Render the homepage's research-backed Google and AI visibility sections through a synchronously imported component so their explanatory content is included in pre-rendered HTML.
- Route conversation and booking CTAs directly to `/book`; reserve `/#contact` for contact details so visitors reach the scheduler without hunting for it.
- Render authority-guide navigation once in RootLayout for `/authority/*`; other pages retain their own headers to avoid duplicates.
- Keep Chris Mefford's personal biography at `/about` with page-specific metadata, so existing About links remain useful.
- Keep local-search finding rules in a pure module beside the public website-check function, with the UI separate from its page, so findings and access rules are testable.
- Keep `/free-audit` as the opportunity-check entry point so existing inbound links continue to work.
- Store opportunity reports and report requests in service-only tables, send server-authored saved reports through the existing email provider, and confirm success only after provider acceptance so reports cannot be forged or falsely marked sent.
- Validate public DNS addresses and every redirect before bounded website fetches, and mark unreadable checks unknown so the checker never invents results.
- Generate AI website assessments server-side from verified checks and provider-returned web sources; retain the original checks and saved-report flow, stream pending responses, and distinguish AI readiness from actual consumer-product visibility because advice must not masquerade as measured rankings.
- Preserve `/services` as a business-growth overview using shared outcome sections, rather than deleting the URL, so inbound links remain useful.
- Booking slot rules live in supabase/functions/_shared/booking-slots.ts (pure, tested from tests/); the single `booking` function handles slots, lead capture, and calendar events so leads are saved even when email fails.
- Keep SMS consent wording and validation in the shared pure consent module; the booking function stores server-authored, timestamped evidence in a service-only append-only table before calendar creation so visitor consent is auditable and never inferred from a phone number.
